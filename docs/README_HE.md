# NetSec - לוח בקרה פורנזי של Wireshark עם למידת מכונה

לוח בקרה פורנזי לקבצי `.pcapng` של Wireshark, בנוי על Dash + scikit-learn
+ PyTorch. טוען עד שני סבבי הקלטה (S1 ו-S2), מריץ במקביל שלושה
מודלי זיהוי אנומליות (‏IsolationForest, ‏DBSCAN, ‏LSTM) ושתי שכבות של
חוקים דטרמיניסטיים, ומצייר עשרות גרפים לאורך תשעה אזורי ניווט:
הקלטה חיה, ניתוח, פרופיל התקנים, ניתוח גלישה, אבטחה, השוואה,
מצאי, תעבורה חיצונית וכיסוי.

## מה הוא עושה

- קורא קבצי `.pcapng` מהדיסק או מקליט תעבורה חיה דרך `tshark`.
- מחלץ מאפיינים ברמת כתובת IP: מספר חבילות, נפח בייטים, גודל
  חבילה ממוצע, יעדים ייחודיים, ספירות SYN ו-RST, ציון פרץ, מידת
  שליטה בתעבורה.
- מריץ שלושה מודלים של למידת מכונה במקביל:
  - **‏IsolationForest** - זיהוי חריגים לכתובת IP בודדת; פרמטר
    `contamination` קבוע ב-0.10 עם `n_estimators=200,
    random_state=42`. (בעבר רצה סריקה של יציבות-seed, אך מדידה
    מול אמת-מידה מתויגת הראתה שאותו ציון F1 מתקבל גם ב-0.10 הקבוע
    בעלות של פי-15 פחות התאמות של היער - הסריקה בוטלה.)
  - **‏DBSCAN** - אשכולות התנהגות, כתובות שלא השתייכו לאף אשכול
    מסומנות.
  - **‏LSTM** - זיהוי אנומליות על ציר הזמן. פועל על גדלי חבילה
    ממוצעים בחלוקה לפרקי זמן של שנייה (עם איפוס לשניות שקטות).
    מסומן כאשר שגיאת החיזוי חורגת מ-`val_mean + 2σ` (שקול בפועל
    ל-`quantile_0.95`). ה-LSTM מתאמן **רק** על הקלטות עם 20
    פרקי-זמן שמישים או יותר (ה-`SEQ_LEN=10` מצריך מינימום של
    10 חלונות גולשים); הקלטות קצרות מדי מדלגות עליו בשקט,
    והחוקים הדטרמיניסטיים מכסים אותן.
- מריץ שתי שכבות חוקים דטרמיניסטיים - **סוס העבודה של הזיהוי**:
  זיהוי סריקות TCP מסוגי SYN, FIN, NULL ו-Xmas, חוק הצפת SYN
  אגרגטיבי עם מקורות מזויפים, ואותות של זיוף ARP, הגברת DNS
  ומנהור DNS. במדידה מול האמת המתויגת, החוקים תופסים מאה אחוז
  מהתוקפים המתויגים בכל קובץ הקלטה של תקיפה - תפקיד שכבת למידת
  המכונה הוא למצוא חריגים שהחוקים לא תפסו, לא לשחזר אותם.
- ציון ה-**fusion** (אזור `Advanced threats`) הוא קורלציה ברמת
  ההתקן בין חמשת מנועי הזיהוי המתקדמים (‏beaconing, מנהור DNS,
  ‏DGA, ‏ARP/DHCP, ‏TLS) בחלון של 15 דקות. הוא מכוון לדפוסי
  חמקנות בסגנון APT ולא נדלק על הקלטות הסריקה או ההגברה הרועשות
  שבאמת המתויגת. זה העיצוב, לא פער.
- מסווג כל התקן שנצפה לאחת מ-12 קטגוריות באמצעות מנוע תלת-שלבי:
  חוקי שם מארח, קידומת יצרן של כתובת MAC ופורטים ← טביעות
  אצבע של DNS ← היוריסטיקה התנהגותית.
- ברגע שסבב שני נטען, הדשבורד מצייר השוואה זו-לצד-זו של S1 מול S2.

## איך מריצים על מחשב נייד

1. התקינו את Wireshark (מספק את `tshark` ואת `mergecap`):
   - Windows: <https://www.wireshark.org/download.html>
2. תלויות Python: `pip install -r requirements.txt` (ה-notebook עדיין
   מתקין אוטומטית חבילות חסרות כנפילה חזרה למחשבים טריים).
3. פתחו את `app/Network_Security_Dashboard.ipynb` ב-Jupyter.
4. לחצו **‏Kernel ← Restart Kernel ← Run All**.
5. פתחו את הכתובת שהתא האחרון מדפיס (בוחר אוטומטית את הפורט הפנוי
   הראשון בטווח 8050-8099).
6. ‏Welcome ← סמנו את תיבת האישור ← ‏Continue ← גררו קובץ PCAPNG
   (או הדביקו נתיב מלא) ← לחצו **‏Load** ← יופיע כרטיס staging
   עם הקובץ ← לחצו **‏▶ Analyze** ← הדשבורד נפתח.
   (‏Load רק מאמת את הקובץ ומכין אותו; הניתוח עצמו רץ רק כשלוחצים
   ▶ Analyze על כרטיס ה-staging. התהליך הדו-שלבי מונע ממסלול
   שהוקלד בטעות להפעיל ריצה ארוכה.)
7. מהדשבורד, **‏+ Load second PCAP** בסרגל הצד מוסיף את סבב ההשוואה
   S2 (אותו תהליך של Load ← ‏▶ Analyze).

**טיפ ל-Windows - נתיבים עם תווים שאינם ASCII** (עברית, קירילית, ‏CJK,
תווים מוטעמים בתוך שם התיקייה): הפעילו את Python עם `PYTHONUTF8=1`
(או עם `python -X utf8 …`) כדי שההדפסות לקונסולה לא יקרסו על
`cp1255` או `cp1252`. נתיבי ASCII רגילים לא זקוקים לכך. דוגמה:

```powershell
$env:PYTHONUTF8=1; jupyter notebook
```

## הרצה על הקלטות משלכם (שלוש דרכים)

בחרו את זו שמתאימה לרמת הנוחות שלכם. שלוש הדרכים מריצות את אותו
צינור זיהוי; ההבדל הוא *היכן* הניתוח רץ ואיך מקבלים את הדוח.

### א. דשבורד אינטראקטיבי + "שליחה ל-VM" (מומלץ)

פתחו את ה-notebook, גררו קובץ PCAP, ולחצו **‏Send S1 to VM (mail
report)** על כרטיס הסבב. הדשבורד חותם על הקובץ, מזרים אותו לשרת
הניתוח שלכם, וה-worker שולח את דוח ה-PDF המוגמר באימייל לכתובת
שהקלדתם - בלי GitHub, בלי תקרת גודל, בלי LLM מקומי.

מה שצריך: שרת ניתוח (דרך ג' מקימה אחד), שלושת משתני הסביבה
`NETSEC_INGEST_URL / NETSEC_SENSOR_ID / NETSEC_SENSOR_SECRET`
ב-shell שלכם לפני שמשיקים את ה-notebook, ו-`SMTP_USER / SMTP_PASS`
בקובץ `.env` של ה-VM (‏Gmail app-password עובד). לפרטי התפעול
המדויקים ראו `docs/VM_OPS.md`.

**מה נוחת בתיבת הדואר שלכם.** גוף האימייל הוא תקציר מנהלים (ספירת
פסיקות, ממצאים מרכזיים עם שורת ראיות אחת, מטה-דאטה של ההקלטה,
בריאות הפאנל); הדוח המלא רוכב כקובץ PDF מצורף, עם באנר פסיקה
צבעוני, טבלת מועמדים מאוחדת, אזור ראיות לכל ממצא (זהות ההתקן,
מספרי התעבורה, אילו שדות קלט השופטים ציטטו), ורשת הצבעות של
הפאנל שמראה את הצבעת כל שופט לכל מועמד. אחרי שניתחתם גם את S1
וגם את S2, הכפתור **‏Compare S1 & S2** שולח באימייל דוח השוואה
מסדר שני: הקלטות זו לצד זו עם פער הזמן ביניהן, טבלת זרימת
קטגוריות של מה שהשתנה, היפוכי פסיקה עם זהות ההתקן, וכתובות IP
חדשות או שנעלמו עם ההערות על הפסיקות שלהן.

### ב. שורת פקודה ללא ממשק על המחשב שלכם

אותו צינור זיהוי, אותו שופט LLM, בלי notebook. שני טעמים:

**‏ב1. ניתוח מקומי + דוח מקומי** (שום דבר לא עוזב את המחשב שלכם):

```
pip install -r requirements.txt
python llm_judge/judge_cli.py path/to.pcap \
    --output verdicts.json --markdown verdicts.md
```

דורש את `tshark` ב-PATH (מותקן עם Wireshark), בתוספת ספק LLM אחד -
‏Ollama למסלול בלי מפתח (`LLM_JUDGE_PROVIDER=ollama`), או
Groq / Gemini / Cerebras / OpenRouter / Anthropic / GitHub Models
עם מפתח משלכם. הגדירו `LLM_JUDGE_PANEL=<m1>,<m2>[,...]` לדיון
אמיתי בין כמה שופטים. ראו `llm_judge_README.md` לכל הכפתורים.

**‏ב2. העלאה ל-VM שלכם + משלוח הדוח באימייל** (זהה לכפתור
הדשבורד, משורת הפקודה):

```
export NETSEC_INGEST_URL=http://<vm-tailscale-ip>:8766
export NETSEC_SENSOR_ID=laptop NETSEC_SENSOR_SECRET=...
python tools/upload_pcap.py capture.pcapng --email you@example.com
```

הדגל `--email` עובר כ-header `X-Notify-Email`; שרשרת הנפילה חזרה
של ה-worker (SMTP → n8n) מספקת את דוח ה-PDF.

### ג. הרצה של שרת ניתוח פעיל-תמיד משלכם (רציף, פרטי)

לניטור רציף שלא תלוי בכך שהמחשב הנייד שלכם ער - וגם לשמור את
הפקטות הגולמיות ברשת שלכם בלבד - הריצו את מערך הניתוח על VM קטן
שבשליטתכם. העיצוב המלא (בעברית, לפי בקשה) נמצא ב-`ARCHITECTURE_SPEC_HE.md`,
ותבניות הפריסה נמצאות ב-`deploy/`.

**מה זה.** ארבע שכבות משתפות פעולה במקום ארבעה כלים מודבקים ב-`scp`:

- **‏Sensor (שכבה 0)** - המחשב הנייד או Raspberry Pi 5 מקליטים
  PCAP גולמי לתוך מאגר טבעתי של `tshark` ומעלים כל חתיכה שנסגרה
  ל-VM. ההקלטה הגולמית - לא CSV דחוס שלה - היא מקור האמת ומה
  שעובר ניתוח.
- **‏Analyzer (שכבה 1)** - ה-VM מריץ API קליטה חתום, ‏worker
  שמריץ את *אותו* צינור הזיהוי של הדשבורד על כל קובץ PCAP,
  ומסד נתונים של היסטוריה ב-SQLite. ‏PCAP גולמיים נשמרים
  שבעה ימים ואז נמחקים אוטומטית; אינדקס שדות דחוס זעיר, הפסיקות
  ודוחות ה-HTML/PDF נשמרים לעד.
- **שופטים (שכבה 2)** - פאנל שופטי ה-LLM הקיים. **‏אתם בוחרים**
  אילו שופטים ירוצו (אחד, שניים, או הרבה ספקים חינמיים: ‏Groq,
  ‏Gemini, ‏Cerebras, ‏OpenRouter, ‏GitHub Models, ועוד Ollama מקומי
  חינמי). כל שופט שבחרתם רץ וכל הפסיקות חוזרות באימייל - אין נפילה
  חזרה אוטומטית שמחליפה מודלים מאחורי הגב שלכם. **הפאנל הנוכחי
  בשרת הייחוס מורכב מ-4 שופטים**: ‏`groq:llama-3.1-8b-instant`,
  `groq:llama-3.3-70b-versatile`, `ollama:qwen2.5:3b` (מקומי,
  מעבד בלבד, כ-55 שניות לפסיקה על ARM 24GB), ו-`gemini:gemini-2.5-flash`
  (‏Google AI Studio באימות Bearer). ה-`ThreadPoolExecutor` מריץ
  את כל הארבעה במקביל, אז זמן השעון שווה בערך למקסימום של השופטים
  ולא לסכום. פירוט מלא ועם קוד נמצא ב-`docs/VM_ARCHITECTURE_SPEC_HE.md`
  סעיף 10, וה-prompt המדויק ב-`docs/LLM_INTERFACE.md`.
- **צרכנים (שכבה 3)** - ה-notebook (כלקוח מרוחק *או* כאנליזר
  מקומי מלא), אימייל, והתראות n8n.

**למה דווקא VM.** אין תקרת גודל (ההעלאה היא הזרמת HTTP חתומה
ישירות), שומר היסטוריה כך ש-beaconing וקווי בסיס לכל התקן הופכים
משמעותיים, ושומר את הפקטות הגולמיות על תשתית שבבעלותכם. מסלול
ה-Actions ("‏דחפו PCAP לתיקיית `incoming/`") שהיה כאן בוטל - תקרת
25 MB של Actions הפכה אותו לבלתי שמיש להקלטות אמיתיות, ומסלול
ה-VM מכסה כל מקרה שהיה בטיפולו.

**התחלה מהירה** (מדריך מלא ב-`deploy_README.md`):

```bash
# על ה-VM (כל קופסה של Ubuntu 22.04+; Oracle Always Free הוא מסלול ה-0$)
git clone <your-fork> && cd <repo>/deploy
cp .env.example .env          # הגדירו TS_BIND, N8N_ENCRYPTION_KEY, מפתחות LLM
docker compose up -d          # n8n + ingest API + worker + retention
python3 create_sensor.py laptop   # מדפיס את אישורי החיישן פעם אחת

# על כל מחשב שיש בו הקלטה (בלי תקרת גודל, בלי GitHub)
export NETSEC_INGEST_URL=http://<vm-tailscale-ip>:8766
export NETSEC_SENSOR_ID=laptop NETSEC_SENSOR_SECRET=...
python3 tools/upload_pcap.py capture.pcapng
```

ה-VM עונה אך ורק על רשת ה-Tailscale הפרטית שלכם (שום דבר לא פומבי
מלבד SSH). סקריפט חיצוני `tools/watchdog.py` רץ על קופסה נפרדת
פעילה-תמיד ומנטר את ה-VM, כי אף מחשב אינו אמור לנטר את עצמו.

**העשרה אופציונלית של OSINT.** עם מפתחות API חינמיים משלכם,
ה-VM יכול להוסיף הקשר ציבורי למה שההקלטה ראתה, הכל כבוי כברירת
מחדל:

- **‏Wigle** מאתר BSSID של Wi-Fi שנתפס וה-VM מצייר מפת גיאו של
  נקודות הגישה (`report kind: map`), עם ציון של ה-RSSI והמרחק
  (לפי אובדן נתיב) שהצינור כבר מחשב.
- **‏Shodan** נותן ציון מוניטין למארח חיצוני שהתקן מקומי דיבר
  אתו (CVE ידועים, תוויות זדוניות); זה מפעיל את משקל ה-threat
  intel השמור של השופט, כך ש"ההתקן הזה מדבר עם מארח מסומן"
  מרים את העדיפות של המועמד.

הגדירו `WIGLE_API_NAME`/`WIGLE_API_TOKEN`, ‏`SHODAN_API_KEY` ו-
`NETSEC_ENABLE_SHODAN=1` ב-`deploy/.env`. בלי מפתחות המפה נשארת
ריקה ומשקל ה-מודיעין איומים לא תורם דבר - התנהגות זהה לבסיס.

**כל מה שלמעלה אופציונלי.** ה-notebook של הדשבורד המקומי עדיין
מנתח קובץ בלי VM ובלי רשת בכלל; מסלול ה-VM הוא מה שהופך notebook
חד-פעמי למערכת רציפה ששולחת לתיבת הדואר שלכם.

**ניהול שוטף של ה-VM.** אחרי ההקמה החד-פעמית, כל הפעולות הנפוצות -
כניסה ב-SSH, פריסה מחדש אחרי `git pull`, צפייה בריצה חיה,
אתחול שירות, גיבוי מסד הנתונים ההיסטורי, החלפת חיישן שנפרץ -
מרוכזות ב-[`docs/VM_OPS.md`](docs/VM_OPS.md) כבלוקי פקודה
מוכנים להדבקה. המסמך משתמש במחליפים `<vm>` ו-`<sensor>` בכל
מקום; החליפו בכתובת ה-Tailscale ובשם החיישן שלכם פעם אחת והשאר
פשוט יעבוד.

## בדיקות

```
pip install -r requirements.txt -r server/requirements.txt pytest pytest-timeout
pytest tests/ -v
```

הסוויטה דורשת את `tshark` ב-PATH (מגיע עם Wireshark).
`server/requirements.txt` מספק את `fastapi`, ‏`uvicorn` ו-`httpx`
בשימוש של ה-API של הקליטה ושל בדיקות קצה-לקצה - בלעדיהם הן היו
נדלגות בשקט. אפשר גם להריץ את צינור הרגרסיה הידני של שורת הפקודה
ישירות על כל זוג הקלטות:

```
python3 attack_tests/run_pipeline.py <S1.pcap> <S2.pcap>
```
